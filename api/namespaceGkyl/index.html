    function calc_bkg_flow

    void Gkyl::calc_bkg_flow (
    grid_data_t & grid_data,
    Vectors::Vector4D < BkgFPType > & gkyl_uz,
    Vectors::Vector4D < BkgFPType > & gkyl_uX,
    Vectors::Vector4D < BkgFPType > & gkyl_uY,
    Vectors::Vector4D < BkgFPType > & gkyl_uZ,
    const Vectors::Vector4D < BkgFPType > & gkyl_bX,
    const Vectors::Vector4D < BkgFPType > & gkyl_bY,
    const Vectors::Vector4D < BkgFPType > & gkyl_bZ,
    Vectors::Vector4D < BkgFPType > & gkyl_eX,
    Vectors::Vector4D < BkgFPType > & gkyl_eY,
    Vectors::Vector4D < BkgFPType > & gkyl_eZ,
    Vectors::Vector4D < BkgFPType > & gkyl_dbdX,
    Vectors::Vector4D < BkgFPType > & gkyl_dbdY,
    Vectors::Vector4D < BkgFPType > & gkyl_dbdZ,
    Vectors::Vector4D < BkgFPType > & gkyl_viperp_sq,
    const Options::Options & opts
)

    Calculates the Cartesian components of the background ion flow.

    The flow is the projection of the parallel-to-z flow onto the magnetic field direction, plus the ExB drift, E x B / B^2, plus the grad-B drift, (m v_perp^2 / (2 q B^3)) B x grad(B). The ions are assumed to be singly charged.

    Parameters:

    • grid_data Tuple of the time and grid vectors (see read_gkyl).
    • gkyl_uz Ion flow parallel to z (m/s).
    • gkyl_uX Array the X component of the flow (m/s) is stored in.
    • gkyl_uY Array the Y component of the flow (m/s) is stored in.
    • gkyl_uZ Array the Z component of the flow (m/s) is stored in.
    • gkyl_bX Magnetic field X component (T).
    • gkyl_bY Magnetic field Y component (T).
    • gkyl_bZ Magnetic field Z component (T).
    • gkyl_eX Electric field X component (V/m).
    • gkyl_eY Electric field Y component (V/m).
    • gkyl_eZ Electric field Z component (V/m).
    • gkyl_dbdX X component of grad(B) (T/m).
    • gkyl_dbdY Y component of grad(B) (T/m).
    • gkyl_dbdZ Z component of grad(B) (T/m).
    • gkyl_viperp_sq Ion perpendicular thermal velocity squared (m^2/s^2).
    • opts Simulation options, used for the ion mass.

    template<typename T>
void Gkyl::calc_gradients (
    grid_data_t & grid_data,
    const Vectors::Vector4D < BkgFPType > & gkyl_vp,
    Vectors::Vector4D < BkgFPType > & gkyl_eX,
    Vectors::Vector4D < BkgFPType > & gkyl_eY,
    Vectors::Vector4D < BkgFPType > & gkyl_eZ,
    Vectors::Vector4D < BkgFPType > & gkyl_emag,
    const Vectors::Vector4D < BkgFPType > & gkyl_bmag,
    Vectors::Vector4D < BkgFPType > & gkyl_dbdX,
    Vectors::Vector4D < BkgFPType > & gkyl_dbdY,
    Vectors::Vector4D < BkgFPType > & gkyl_dbdZ,
    const Vectors::Vector4D < T > & gkyl_dxdX,
    const Vectors::Vector4D < T > & gkyl_dxdY,
    const Vectors::Vector4D < T > & gkyl_dxdZ,
    const Vectors::Vector4D < T > & gkyl_dydX,
    const Vectors::Vector4D < T > & gkyl_dydY,
    const Vectors::Vector4D < T > & gkyl_dydZ,
    const Vectors::Vector4D < T > & gkyl_dzdX,
    const Vectors::Vector4D < T > & gkyl_dzdY,
    const Vectors::Vector4D < T > & gkyl_dzdZ,
    const Options::Options & opts
)

    Calculates the electric field and the magnetic field gradient in Cartesian coordinates.

    The gradients of the potential and the magnetic field magnitude are first calculated in computational coordinates with central differences (forward or backward differences at the edges), assuming a uniform grid. They are then converted to Cartesian components using the reciprocal basis vectors (Eq. 2.6.35 in D'haeseleer), with E = -grad(Vp). The basis vectors are taken from the first time slice.

    Template parameters:

    • T Floating-point type of the basis vectors.

    Parameters:

    • grid_data Tuple of the time and grid vectors (see read_gkyl).
    • gkyl_vp Plasma potential (V).
    • gkyl_eX Array the electric field X component (V/m) is stored in.
    • gkyl_eY Array the electric field Y component (V/m) is stored in.
    • gkyl_eZ Array the electric field Z component (V/m) is stored in.
    • gkyl_emag Array the electric field magnitude (V/m) is stored in.
    • gkyl_bmag Magnetic field magnitude (T).
    • gkyl_dbdX Array the X component of grad(B) (T/m) is stored in.
    • gkyl_dbdY Array the Y component of grad(B) (T/m) is stored in.
    • gkyl_dbdZ Array the Z component of grad(B) (T/m) is stored in.
    • gkyl_dxdX Reciprocal basis vector component dx/dX.
    • gkyl_dxdY Reciprocal basis vector component dx/dY.
    • gkyl_dxdZ Reciprocal basis vector component dx/dZ.
    • gkyl_dydX Reciprocal basis vector component dy/dX.
    • gkyl_dydY Reciprocal basis vector component dy/dY.
    • gkyl_dydZ Reciprocal basis vector component dy/dZ.
    • gkyl_dzdX Reciprocal basis vector component dz/dX.
    • gkyl_dzdY Reciprocal basis vector component dz/dY.
    • gkyl_dzdZ Reciprocal basis vector component dz/dZ.
    • opts Simulation options.

    function check_tdim

    void Gkyl::check_tdim (
    Vectors::Vector4D < BkgFPType > & gkyl_arr,
    const Options::Options & opts
)

    Checks that the number of frames in the loaded background matches that requested for the simulation, stopping the run with Errors::fatal_error if not.

    This only needs to be run once. It is useful if the user is reusing an already calculated background, but changed the frames in the input file. In that case the background files should be deleted so that they can be regenerated, since the default is to read any existing files. Note you can circumvent this error checking if the range of frames stays the same, but that's a fringe case and not worth the effort to protect against at the moment.

    Parameters:

    • gkyl_arr Any loaded array with dimensions (t, x, y, z).
    • opts Simulation options, used for gkyl_frame_start and gkyl_frame_end.

    function get_read_gkyl_py

    std::string Gkyl::get_read_gkyl_py ()

    Returns the full path to read_gkyl.py, which is used to interface with postgkyl and create files that are easily read in by Flan.

    The path is stored in the READ_GKYL_PY environment variable, which is set before Flan is run. If it is not set, the run is stopped with Errors::fatal_error, since the background can't be read without it.

    Returns:

    Full path to read_gkyl.py.

    function gradient_ybound_fix

    void Gkyl::gradient_ybound_fix (
    grid_data_t & grid_data,
    Vectors::Vector4D < BkgFPType > & ecomp
)

    Applies a fix to the y boundaries of gradient-calculated data, where the gradient generally messes up due to not as many points around.

    The y boundaries are treated as periodic, and the first and last cells in y are replaced with weighted averages of the second and second to last cells. This is generally a hack, since it is not clear what to do in this situation. Ideally, the gradient calculation would handle this, but I haven't been able to figure it out. Currently unused.

    Parameters:

    • grid_data Tuple of the time and grid vectors (see read_gkyl).
    • ecomp Gradient-calculated data to fix in place.

    function load_grid

    std::tuple< std::vector< BkgFPType >, std::vector< BkgFPType >, std::vector< BkgFPType > > Gkyl::load_grid ()

    Reads in the x, y, z grid edges from bkg_from_pgkyl_grid.csv.

    Lines starting with # are comments. The first line holds the number of grid edges in x, y and z. Then all the x values are listed, then the y values, then the z values, one per line. The run is stopped with Errors::fatal_error if there are not 3 dimensions or there are too many values.

    Returns:

    Tuple of the grid edges in x, y and z.

    function load_interp_settings

    std::vector< std::string > Gkyl::load_interp_settings ()

    Reads in the interpolation settings used by Gkeyll from bkg_from_pgkyl_interp_settings.csv.

    This file is made automatically by read_gkyl.py when loading datasets that include these settings, so they are available for files which do not include them (like the magnetic field data).

    Returns:

    Vector of two elements: the basis type and the polynomial order.

    function read_data_pgkyl

    template<typename T>
void Gkyl::read_data_pgkyl (
    const std::string & species,
    const std::string & data_type,
    grid_data_t & grid_data,
    Vectors::Vector4D < T > & gkyl_data,
    const Options::Options & opts,
    const double species_mass_amu,
    const bool force_load
)

    Reads in a Gkeyll dataset using a python interface to postgkyl, read_gkyl.py.

    Species-specific data (density, temperature, par_flow and vperp_sq) is saved to bkg_from_pgkyl_[species]_[data_type].bin, and everything else to bkg_from_pgkyl_[data_type].bin. If that file already exists it is loaded directly, unless force_load is true. Otherwise read_gkyl.py is called to create it. The magnetic field and geometry files don't include the DG interpolation settings, so for those the settings saved when an earlier dataset was loaded are passed to read_gkyl.py.

    Either way, the times, grid edges and cell centers in grid_data are also loaded.

    Template parameters:

    • T Floating-point type of the values.

    Parameters:

    • species Name of the Gkeyll species. Not used by data that isn't species-specific.
    • data_type Name of the dataset to load, e.g., density, temperature, potential or magnetic_magnitude.
    • grid_data Tuple of the time and grid vectors (see read_gkyl).
    • gkyl_data Array the values are moved into, with dimensions (t, x, y, z).
    • opts Simulation options.
    • species_mass_amu Mass of the species (amu), needed to calculate the temperature.
    • force_load If true, call read_gkyl.py even if the file already exists.

    function read_gkyl

    Background::Background Gkyl::read_gkyl (
    const Options::Options & opts
)

    Entry point for reading Gkeyll data into Flan.

    Each needed dataset is loaded from the Gkeyll case, either by calling read_gkyl.py through postgkyl or, if they already exist, from the files it saved on a previous run. The electric field and magnetic field gradient are then calculated, along with the background flow if the moments are BiMaxwellian. Finally every array is moved (not copied) into a Background object.

    Time-dependent data is 4D with dimensions (t, x, y, z). Time- independent data (the Jacobian, metric coefficients, basis vectors and covariant components of the magnetic field) is read in as 4D, and a single time slice is stored as 3D (x, y, z). In both cases the arrays are indexed according to the Gkeyll computational coordinate indices.

    This file uses the convention that all variable names are lowercase, except x,y,z always refers to computational (Gkeyll, curvilinear) coordinates and X,Y,Z always refers to physical (Cartesian) coordinates.

    Parameters:

    • opts Simulation options.

    Returns:

    Background object holding the Gkeyll data.

    function read_magnetic_field

    template<typename T>
void Gkyl::read_magnetic_field (
    grid_data_t & grid_data,
    Vectors::Vector4D < T > & gkyl_bX,
    Vectors::Vector4D < T > & gkyl_bY,
    Vectors::Vector4D < T > & gkyl_bZ,
    Vectors::Vector4D < T > & gkyl_bR,
    Vectors::Vector4D < T > & gkyl_bmag,
    const Options::Options & opts
)

    Reads in the magnetic field and calculates its Cartesian components.

    Gkeyll provides the Cartesian components of the magnetic field unit vector and the magnitude. The unit vector is not guaranteed to have a magnitude of 1.0 at the cell centers, so each one is renormalized to 1.0 and then multiplied by the magnitude. The number of unit vectors with a magnitude outside [0.95, 1.05] is printed. bR is the magnitude of the X-Y components.

    Template parameters:

    • T Floating-point type of the values.

    Parameters:

    • grid_data Tuple of the time and grid vectors (see read_gkyl).
    • gkyl_bX Array the X component (T) is moved into.
    • gkyl_bY Array the Y component (T) is moved into.
    • gkyl_bZ Array the Z component (T) is moved into.
    • gkyl_bR Array sqrt(bX^2 + bY^2) (T) is stored in.
    • gkyl_bmag Array the magnitude (T) is moved into.
    • opts Simulation options.
