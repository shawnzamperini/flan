    Running Flan

    A Flan simulation is a case: a directory with an input file, which is a small C++ program that sets the options and calls Flan. Running one takes four steps:

    1. Set up a case directory with flan_setup.sh.
    2. Set the options in the input file.
    3. Compile it with make.
    4. Run it, from the command line or with a job script.

    This page assumes Flan is installed (see Installation). Activate the flan conda environment before any of these steps:

    conda activate flan

    The environment has the paths Flan needs to read Gkeyll data. A Gkeyll run without it stops with an error saying READ_GKYL_PY is not set.

    Set up a case

    Create a case directory with the setup script, which is made when Flan is built:

    /path/to/flan/scripts/flan_setup.sh my_case
cd my_case

    This creates my_case/ with:

    • my_case.cpp: the input file, a copy of regression/blank_input_file.cpp to start from.
    • CMakeLists.txt and the Makefile made from it, which compile the input file against the installed Flan library.

    The executable is named after the case, and it's built from the .cpp file with the same name, so keep the two names the same.

    The input file

    The input file sets the options in create_inputs and passes them to Flan:

    #include "flan.h"
#include "mpi.h"

Inputs create_inputs()
{
    Inputs inpts;

    inpts["case_name"] = "my_case";
    inpts["imp_num"] = 100000;
    inpts["imp_time_step"] = 1e-8;
    inpts["imp_atom_num"] = 74;
    inpts["imp_mass_amu"] = 183.84;
    // ... any other options

    return inpts;
}

int main(int argc, char* argv[])
{
    MPI_Init(&argc, &argv);
    Inputs inpts {create_inputs()};
    flan(inpts);
    MPI_Finalize();
}

    Every option is listed on the Input Options page, and any option you don't set uses its default. The value has to have the option's type: inpts["imp_num"] = 1e5 is a double, so it stops the run for an int option, while inpts["imp_num"] = 100000 works. An option name that isn't recognized, e.g., from a typo, also stops the run, before the simulation starts.

    The blank input file turns on ionization/recombination, which needs the OpenADAS rate coefficient files. These aren't installed with Flan. Download them from open.adas.ac.uk and set openadas_root to the directory they're in (see Ionization/Recombination for the layout Flan expects).

    Compile

    make

    This builds the executable my_case. Run make again after every change to the input file, and after reinstalling Flan.

    Run from the command line

    ./my_case

    This runs on one MPI rank, using as many OpenMP threads as OpenMP chooses, usually one per core. To set the number of threads, e.g., to 8:

    OMP_NUM_THREADS=8 ./my_case

    To run on several MPI ranks, e.g., 2, with 8 threads each:

    OMP_NUM_THREADS=8 mpiexec -n 2 ./my_case

    Your system may use mpirun or srun instead of mpiexec. On a laptop or workstation, one rank with all the cores as threads is usually best. Several ranks are for spreading a run across the nodes of a cluster. Every rank holds its own copy of the background plasma, so more ranks on one machine use more memory, while more threads don't.

    GPUs

    With a GPU build of Flan installed, set inpts["use_gpu"] = "cuda" to follow the particles on the GPUs. Each rank uses every GPU it can see, so run one rank per node (see MPI Parallelism).

    What a run does

    Flan prints a short banner with the version and the number of ranks and threads, then loads the options and the background. While particles are followed it prints progress updates (print_interval controls how many), and at the end, any warnings and a summary of where the time went.

    The results are saved to <case_name>.nc, a netCDF file with four groups:

    Group Contents
    input Every input option used in the run.
    geometry The times, the grid and the geometry of the background.
    background The background plasma: density, temperatures, fields and flow.
    output The impurity results: counts, density nz, average velocities, average charge and Nanbu s.

    The 4D arrays have dimensions (time, x, y, z). The file can be read with any netCDF reader, e.g., netCDF4 in Python. The flan environment also has flan_plots, with plotting helpers for Flan output:

    import flan_plots

fp = flan_plots.FlanPlots("my_case.nc")
fp.plot_frame_xy("nz", frame=0, z0=0.0)  # Impurity density at z = 0

    Gkeyll files

    A run with a Gkeyll background reads the Gkeyll output files from gkyl_dir. Each file name starts with gkyl_casename. In the names below, <case> is gkyl_casename, <elc> and <ion> are gkyl_elec_name and gkyl_ion_name (elc and ion by default), and <n> is the frame number, for every frame from gkyl_frame_start to gkyl_frame_end.

    These files are needed for every frame. Which moment files are needed depends on gkyl_moment_type:

    gkyl_moment_type Files for each frame
    "bimaxwellian" (default) <case>-<elc>_BiMaxwellianMoments_<n>.gkyl
    <case>-<ion>_BiMaxwellianMoments_<n>.gkyl
    "maxwellian" <case>-<elc>_MaxwellianMoments_<n>.gkyl
    <case>-<ion>_MaxwellianMoments_<n>.gkyl
    "m0m1m2" <case>-<elc>_M0_<n>.gkyl
    <case>-<elc>_prim_moms_<n>.gkyl
    <case>-<ion>_prim_moms_<n>.gkyl

    The potential, <case>-field_<n>.gkyl, is needed for every frame, whatever the moment type.

    The geometry files are read once. They have no frame number:

    File What Flan uses it for
    <case>-bmag.gkyl Magnetic field strength
    <case>-bcart.gkyl Direction of the magnetic field, in Cartesian (X, Y, Z) components
    <case>-b_i.gkyl Covariant components of the magnetic field direction
    <case>-jacobgeo.gkyl Jacobian
    <case>-gij.gkyl Metric coefficients, saved to the output for post-analysis
    <case>-dxdz.gkyl Tangent basis vectors
    <case>-dzdx.gkyl Reciprocal basis vectors, used to calculate the electric field and the gradient of B

    For example, with gkyl_casename = "d3d" and the default species names, frame 5 needs d3d-elc_BiMaxwellianMoments_5.gkyl, d3d-ion_BiMaxwellianMoments_5.gkyl and d3d-field_5.gkyl.

    From the moments, Flan reads the electron density and the electron and ion temperatures. The ion density isn't used. Only the "bimaxwellian" files have the ion parallel flow and perpendicular thermal velocity. Flan uses these to calculate the background flow, so collisions need "bimaxwellian" (see Input Options). Only Gkeyll's binary .gkyl format can be read.

    Once the bkg_from_pgkyl_* files have been saved (see below), Flan doesn't read the Gkeyll files again.

    Gkeyll background files

    The first time a case runs with a Gkeyll background, Flan reads the Gkeyll data with postgkyl and saves it as bkg_from_pgkyl_* files in the case directory. Later runs load those files directly, which is much faster.

    Delete the background files after changing the background

    The saved files are reused no matter what the Gkeyll options say. If you change gkyl_dir, gkyl_casename, the frames or the species, delete the bkg_from_pgkyl_* files so they're made again. Flan stops if the number of frames doesn't match, but it can't catch every change.

    Example: the ExB drift test

    The test cases in regression/ are complete input files. To run the ExB drift test, which follows 100 particles through constant electric and magnetic fields:

    /path/to/flan/scripts/flan_setup.sh test_exb
cd test_exb
cp /path/to/flan/regression/test_exb.cpp .
make
./test_exb

    The copy replaces the blank input file, since it has the same name. The results are in exb.nc, named after its case_name.

    Troubleshooting

    If a run stops with an Error! message, the message says what's wrong, e.g., an option name or value, a missing file or a background that doesn't match the options. For anything else, contact Shawn Zamperini (zamperinis@fusion.gat.com).
